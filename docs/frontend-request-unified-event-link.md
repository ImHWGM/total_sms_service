# 프론트엔드 수정 요청서: 행사 통합 링크 페이지

## 배경

기존에는 참가자에게 **RSVP 링크**(사전설문)와 **QR 링크**(출석확인)를 각각 별도로 발송했습니다.
이번 백엔드 변경으로 **하나의 통합 링크**만으로 두 기능을 모두 처리할 수 있게 되었습니다.

참가자가 통합 링크에 접속하면, **서버가 현재 시점에 맞는 모드를 판단**하여 응답합니다.
프론트엔드는 이 모드 값에 따라 적절한 화면을 렌더링하면 됩니다.

---

## 1. 신규 페이지 생성

### 통합 링크 페이지

- **경로**: `/event/{eventSeq}/check/{checkCode}`
- **인증**: 불필요 (공개 페이지)
- `eventSeq`와 `checkCode`는 URL 파라미터에서 추출

---

## 2. API 명세

### 2-1. 상태 조회

페이지 진입 시 호출합니다.

```
GET /api/front/event/check/{eventSeq}/{checkCode}/state
```

**응답 예시:**

```json
{
  "success": true,
  "data": {
    "mode": "RSVP",
    "participant": {
      "name": "홍길동",
      "checkCode": "ABC123"
    },
    "qrCodeUrl": null,
    "registType": null,
    "preSurveyActive": true,
    "nonce": "a1b2c3d4e5f6..."
  }
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `mode` | string | `"RSVP"` / `"RSVP_ANSWERED_ATTEND"` / `"RSVP_ANSWERED_ABSENT"` / `"QR_ONLY"` |
| `participant.name` | string | 참가자 이름 |
| `participant.checkCode` | string | 체크인 코드 |
| `qrCodeUrl` | string / null | QR 코드 생성용 URL. `QR_ONLY`, `RSVP_ANSWERED_ATTEND` 모드에서만 값 있음 |
| `registType` | string / null | 현재 응답 상태 (한국어: `"사전등록"`, `"불참석"` 등) |
| `preSurveyActive` | boolean | 사전설문 기간 여부 |
| `nonce` | string / null | RSVP 제출 시 필요한 일회용 토큰. `QR_ONLY`에서는 null |

### 2-2. RSVP 제출

참가자가 "참석" 또는 "불참" 버튼을 누를 때 호출합니다.

```
POST /api/front/event/check/{eventSeq}/{checkCode}/rsvp
Content-Type: application/json
```

**요청 body:**

```json
{
  "response": "attend",
  "nonce": "a1b2c3d4e5f6..."
}
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `response` | string | Y | `"attend"` (참석) 또는 `"absent"` (불참) |
| `nonce` | string | Y | 상태 조회 시 발급받은 nonce |

**응답 예시:**

```json
{
  "success": true,
  "data": {
    "registType": "사전등록",
    "prevRegistType": null
  }
}
```

## 3. 화면별 구현 가이드

### 모드별 화면 분기

`mode` 값에 따라 아래와 같이 렌더링합니다.

### 3-1. `QR_ONLY` 모드

> 사전설문 기간이 아닌 경우 (행사 당일 등)

```
┌─────────────────────────┐
│                         │
│    {참가자 이름}님       │
│                         │
│    ┌───────────────┐    │
│    │               │    │
│    │   QR 코드     │    │
│    │               │    │
│    └───────────────┘    │
│                         │
│    출석확인용 QR코드     │
│                         │
└─────────────────────────┘
```

- `qrCodeUrl` 값으로 QR 코드 이미지 생성
- 기존 QR 출석확인 페이지와 동일한 UX

### 3-2. `RSVP` 모드

> 사전설문 기간 중, 아직 응답하지 않은 상태

```
┌─────────────────────────┐
│                         │
│    {참가자 이름}님       │
│    참석 여부를 알려주세요 │
│                         │
│  ┌──────────────────┐   │
│  │    참석합니다     │   │
│  └──────────────────┘   │
│                         │
│  ┌──────────────────┐   │
│  │   불참합니다      │   │
│  └──────────────────┘   │
│                         │
└─────────────────────────┘
```

- "참석합니다" 클릭 → `response: "attend"` + `nonce` 로 POST
- "불참합니다" 클릭 → `response: "absent"` + `nonce` 로 POST
- 제출 성공 후 → 상태 조회 API 재호출하여 화면 갱신

### 3-3. `RSVP_ANSWERED_ATTEND` 모드

> 사전설문 기간 중, "참석"으로 응답한 상태

```
┌─────────────────────────┐
│                         │
│    {참가자 이름}님       │
│    참석이 확인되었습니다  │
│                         │
│    ┌───────────────┐    │
│    │               │    │
│    │   QR 코드     │    │
│    │               │    │
│    └───────────────┘    │
│                         │
│    행사 당일 제시해주세요 │
│                         │
│  ┌──────────────────┐   │
│  │  응답 변경하기    │   │
│  └──────────────────┘   │
│                         │
└─────────────────────────┘
```

- QR 코드 + 참석 확인 메시지 동시 표시
- "응답 변경하기" 버튼 → RSVP 모드 화면으로 전환 (선택사항)

### 3-4. `RSVP_ANSWERED_ABSENT` 모드

> 사전설문 기간 중, "불참"으로 응답한 상태

```
┌─────────────────────────┐
│                         │
│    {참가자 이름}님       │
│    불참으로 응답하셨습니다│
│                         │
│  ┌──────────────────┐   │
│  │  응답 변경하기    │   │
│  └──────────────────┘   │
│                         │
└─────────────────────────┘
```

- QR 코드 **없음**
- "응답 변경하기" 버튼 → RSVP 모드 화면으로 전환 (선택사항)

## 4. 에러 처리

| HTTP 상태 | 상황 | 사용자 메시지 |
|---|---|---|
| 404 | checkCode가 잘못됨 / 참가자 없음 | "유효하지 않은 링크입니다." |
| 429 | 요청 너무 빈번 (1초 1회 제한) | "잠시 후 다시 시도해 주세요." |
| 400 | nonce 만료 또는 이미 사용됨 | "페이지를 새로고침 후 다시 시도해 주세요." → 자동으로 /state 재호출 |
| 403 | 사전설문 기간이 아닌데 RSVP 제출 시도 | "현재 사전설문 기간이 아닙니다." |

### nonce 만료 자동 복구

nonce는 **5분 TTL**이므로, 사용자가 페이지를 오래 열어두면 만료될 수 있습니다.
RSVP 제출이 nonce 에러로 실패하면:

1. 상태 조회 API(`/state`) 재호출 → 새 nonce 발급
2. 사용자에게 다시 버튼을 누르도록 안내

## 5. 관리자 페이지 변경 (행사 생성/수정)

행사 생성 및 수정 화면에 **사전설문 기간** 입력 필드를 추가해야 합니다.

### 추가 필드

| 필드명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `preSurveyStartDate` | datetime | N | 사전설문 시작일시 |
| `preSurveyEndDate` | datetime | N | 사전설문 종료일시 |

### 검증 규칙

- 둘 다 비우거나, 둘 다 입력 (하나만 입력 시 에러)
- 종료일 >= 시작일
- 비워두면 기존처럼 QR 전용으로 동작 (통합 링크에서 항상 QR_ONLY)

### 전달 형식

기존 행사 생성/수정 API에 같이 보내면 됩니다.

```json
{
  "eventName": "...",
  "startDate": "...",
  "preSurveyStartDate": "2026-04-01T09:00:00",
  "preSurveyEndDate": "2026-04-07T23:59:59",
  ...
}
```
